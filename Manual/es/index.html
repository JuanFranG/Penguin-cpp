02 / HAZ FUNCIONAR TU PRIMER PROGRAMA

Tu primer programa C++

  1. Crea un archivo de código. Elige File → New → Source File o pulsa New Document en la bienvenida.
  2. Escribe este programa. Muestra una línea y termina correctamente.
    #include <iostream>

int main() {
    std::cout << "Hello, Penguin!" << std::endl;
    return 0;
}
  3. Guárdalo como hello.cpp. Elige una carpeta en la que puedas escribir. La extensión .cpp indica a Penguin que el archivo es C++.
  4. Selecciona una configuración de compilación nativa. Para empezar, elige la configuración Release del compilador del sistema en la barra superior.
  5. Compila y ejecuta. Pulsa F11 (fn + F11 en los Mac con teclas multimedia) o elige Execute → Compile & Run.

Un programa de consola se abre en una terminal. Al finalizar, el resumen informa del resultado y espera una entrada antes de cerrarse. No necesitas system("pause") solo para mantenerla abierta.

Si la compilación falla, revisa las pestañas Compiler y Compile Log. Corrige el primer error relevante y vuelve a compilar; una compilación fallida no ejecuta un archivo antiguo.

04 / ENTIENDE LA COMPILACIÓN

Compilar, ejecutar y reconstruir

AcciónTeclaResultado
CompileF9Compila el archivo o proyecto actual sin ejecutarlo.
RunF10Ejecuta el programa. Vuelve a compilar después de cambiar el código o las opciones.
Compile & RunF11Guarda cuando es necesario, compila y ejecuta solo si la compilación termina correctamente.
RebuildF12Reconstruye el programa, incluidas las fuentes que requieren regeneración.

¿Release, Debug o Profiling?

Release es la configuración habitual para ejecutar. Debug incluye información para el depurador. Profiling instrumenta el código nativo para analizarlo. Cambiar la configuración no reconstruye por sí solo el ejecutable.

Entiende el error antes de cambiar opciones

Un error de sintaxis apunta al código. Una cabecera ausente suele indicar un destino incorrecto o un problema con las rutas de inclusión. Una referencia sin definir es un problema de enlazado: revisa las implementaciones, las bibliotecas y los argumentos del enlazador. Consulta la orden completa en Compile Log cuando el mensaje breve no baste.

Los argumentos del programa van en Parameters, no en las opciones del compilador.

05 / MANTÉN TUS ARCHIVOS JUNTOS

Trabaja con un proyecto

  1. Abre New Project, elige una plantilla adecuada y guarda el archivo .dev en una carpeta propia.
  2. Añade las fuentes y cabeceras desde el menú Project. Una cabecera suele contener declaraciones; también debes compilar la fuente correspondiente si contiene implementaciones.
  3. Usa Project Options para las carpetas de inclusión, bibliotecas, argumentos y rutas de salida de ese proyecto.
  4. Compila y revisa las órdenes en el panel de salida. Guarda el proyecto antes de moverlo a otro equipo.

Mantén juntos el código, los recursos y el archivo del proyecto. Las bibliotecas externas deben corresponder a la plataforma y arquitectura correctas; no puedes enlazar directamente una biblioteca Windows con un ejecutable nativo de macOS.

Quitar una entrada del proyecto es distinto de decidir qué archivos borrar del disco. Comprueba la selección y conserva una copia antes de usar acciones de eliminación o limpieza.

Un proyecto con cabecera y varios archivos

El ejemplo separa la declaración de una función, su implementación y el programa que la llama. Descarga el proyecto completo, extráelo y abre Tutorial.dev con File → Open. Elige tu compilador nativo y pulsa F11. El resultado esperado es Result: 5.

Para crearlo tú mismo, sigue estos pasos:

  1. Abre File → New → Project, selecciona Console Application y C++, y guarda Tutorial.dev en una carpeta propia.
  2. Crea y guarda los tres archivos que aparecen debajo en esa misma carpeta. Usa File → New → Source File; al guardar, escribe la extensión completa, incluida .h para la cabecera.
  3. Asegúrate de que los tres aparecen en el árbol del proyecto. Si falta alguno, añádelo con Project → Add to project. No basta con abrirlo en una pestaña.
  4. En Project Options → Files, comprueba que los dos .cpp se compilan y enlazan. La cabecera se incluye desde ellos; no se compila como programa independiente.
  5. Pulsa F11. En Compile Log deben aparecer ambos archivos de código en la construcción, no solo el activo.

calculator.h

#ifndef TUTORIAL_CALCULATOR_H
#define TUTORIAL_CALCULATOR_H

int add(int left, int right);

#endif

calculator.cpp

#include "calculator.h"

int add(int left, int right) {
    int total = left + right;
    return total;
}

main.cpp

#include <iostream>
#include "calculator.h"

int main() {
    // TODO: try other values
    int result = add(2, 3);
    std::cout << "Result: " << result << std::endl;
    return 0;
}

Qué hace cada archivo

calculator.h declara que existe add. Su guarda #ifndef / #define / #endif evita incluir esa declaración repetidamente dentro de una misma unidad de compilación. calculator.cpp define la función; main.cpp la llama.

Usa #include "calculator.h" para esta cabecera local. Reserva los corchetes angulares para cabeceras del sistema o de bibliotecas configuradas. No uses #include "calculator.cpp": añade esa implementación al proyecto y deja que se compile y enlace.

Si aparece «cabecera no encontrada», revisa el nombre, las mayúsculas y las rutas de inclusión. Si aparece «referencia sin definir» o «símbolo sin definir» para add, comprueba que calculator.cpp esté en el proyecto, que participe en el enlazado y que la firma coincida con la cabecera. Reconstruye después de cambiar estas opciones.

Dónde están las banderas del compilador y del enlazador

Las banderas son argumentos de las herramientas de construcción. Las opciones de un proyecto y las de una configuración global tienen ámbitos distintos:

Qué necesitasRuta de la interfaz en inglésUso
Elegir compilador y opciones estructuradas del proyectoProject → Project Options → CompilerSelecciona una configuración y sus opciones disponibles.
Argumentos adicionales solo de este proyectoProject → Project Options → ParametersSepara las opciones de C, de C++ y del enlazador.
Rutas de cabeceras y bibliotecasProject → Project Options → DirectoriesAñade carpetas; no el nombre de cada cabecera. Prefiere rutas relativas para compartir el proyecto.
Opciones estructuradas de una configuración globalTools → Compiler Options → SettingsAfectan a la configuración seleccionada, que puede usarse en varios proyectos.
Argumentos adicionales globalesTools → Compiler Options → GeneralActiva la casilla correspondiente antes de escribir argumentos de compilación o enlazado.
Carpetas de ejecutables y objetos generadosProject → Project Options → OutputOrganiza la salida sin mezclarla con las fuentes.

El ejemplo utiliza -std=c++17 -Wall -Wextra en el campo C++. -std=c++17 elige el estándar; -Wall -Wextra activa advertencias. Para depurar, selecciona Debug y reconstruye; -g -O0 añade símbolos y facilita seguir el código sin optimización.

Si una biblioteca necesita -L./lib -lname, esos argumentos van en Linker, no en Execute → Parameters, que contiene argumentos del programa en ejecución. Una ruta de inclusión no sustituye la biblioteca que se debe enlazar. Usa binarios compatibles con el sistema y la arquitectura de destino.

Después de aplicar cambios con OK, reconstruye y revisa la orden real en Compile Log. Así confirmas qué opciones llegaron al compilador.

06 / OBSERVA QUÉ HACE TU PROGRAMA

Depura un programa nativo

  1. Selecciona una configuración Debug y reconstruye.
  2. Establece un punto de interrupción en una línea ejecutable con F4 o la acción del margen del editor.
  3. Inicia la depuración con F5. Introduce los datos que pida el programa en su terminal.
  4. Al detenerse, inspecciona las variables vigiladas, la pila de llamadas y la línea actual. F7 avanza sin entrar en una llamada; F8 entra en ella.
  5. Usa F6 para detener la sesión.

Linux utiliza normalmente GDB; macOS, las herramientas nativas de LLDB disponibles. Se siguen aplicando los requisitos de símbolos, permisos de ejecución y restricciones de macOS para adjuntarse a procesos. La ventana CPU necesita un depurador activo y pausado para mostrar registros o desensamblado reales.

Analiza después de reconstruir

Usa Execute → Profile Analysis. Si corresponde, acepta el cambio de configuración propuesto, reconstruye y ejecuta para generar datos. La vista gprof de Linux puede informar de tiempos y del grafo de llamadas. La vista LLVM de macOS muestra cantidades de llamadas a funciones, no tiempos. Consulta el ejemplo real de análisis.

Depura este proyecto paso a paso

  1. Abre el ejemplo anterior, selecciona una configuración nativa Debug y reconstruye con F12.
  2. Abre calculator.cpp desde el árbol del proyecto y coloca un punto de interrupción en return total;, línea 5, con F4.
  3. Inicia con F5. El depurador puede detenerse primero al entrar en main; pulsa el botón Continue del panel Debug para llegar al punto de interrupción.
  4. Pulsa Add watch y añade left, right y total. En esa línea deben valer 2, 3 y 5. Evaluate permite consultar una expresión, por ejemplo left + right.
  5. Usa Next line para avanzar sin entrar en funciones, Into function para entrar en una llamada, Continue para seguir hasta la próxima detención y Stop Execution para terminar.

Consulta la sesión real del ejemplo y la ventana CPU con registros y pila de llamadas. En la pila aparecen add y main. Los registros son ARM64 en este Mac; sus nombres y valores cambian según la arquitectura y la ejecución. La depuración nativa y la ejecución de programas Windows son recorridos distintos.

07 / ELIGE EL DESTINO CORRECTO

Programas que incluyen cabeceras Windows

windows.h no es una API nativa de macOS o Linux. El entorno completo de Penguin puede compilar un ejecutable Windows y ejecutarlo mediante su motor incluido. Abre Tools → Windows compatibility.

ModoCuándo utilizarlo
AutomaticPunto de partida recomendado. Penguin inspecciona los requisitos del proyecto para elegir el destino.
NativeCompila para el macOS o Linux actual con sus herramientas nativas.
WindowsElige explícitamente el compilador y el motor Windows si la selección automática resulta ambigua.

Cuando el entorno indique que está listo, F11 realiza el recorrido de compilación y ejecución. Los programas de consola usan una terminal; los gráficos abren sus ventanas mediante el motor.

Caracteres, bordes y colores

Usa Unicode (UTF-8) para texto nuevo. Prueba OEM 437 con los bordes y caracteres de programas antiguos de estilo DOS, o ANSI 1252 con código escrito para esa página. Program-controlled deja la elección al programa. Vuelve a compilar después de cambiar el perfil de consola.

La compatibilidad es experimental y no garantiza que cualquier proyecto Windows funcione sin cambios. graphics.h/WinBGIm, la depuración de programas Windows, los SDK externos y las bibliotecas específicas de una arquitectura tienen límites adicionales. Las cabeceras estándar como math.h, stdlib.h e <iostream> las proporciona el compilador elegido; la disponibilidad de otras API depende del destino.

10 / RESUELVE SIN ADIVINAR

Cuando algo falla

El compilador no encuentra windows.h o conio.h

Comprueba el destino en Windows compatibility y verifica el entorno completo. Estas cabeceras no se convierten en API nativas de macOS/Linux. Si buscas un programa portable, sustituye las llamadas específicas de plataforma por alternativas estándar de C/C++.

Los caracteres o bordes se ven mal

Revisa la codificación del código y el perfil de consola. Haz coincidir el perfil con la página de códigos esperada y reconstruye. Cambiar la página no añade fuentes ausentes ni reproduce todos los comportamientos históricos de la consola Windows.

No se encuentra ningún compilador

Revisa Compiler Options → Programs y Directories. Instala las herramientas nativas de desarrollo de tu plataforma cuando sean necesarias. El compilador Windows del entorno completo es independiente de las herramientas nativas C/C++ de Apple.

No se puede preparar el entorno Windows

Lee y copia los detalles del error. Comprueba las rutas del compilador y del motor, y que puedas escribir en la carpeta del entorno privado. Reintenta después de corregir la causa. Conserva tus proyectos y preferencias; no los borres para intentar resolver un error de preparación desconocido.

La fuente del código o el margen de números se ve mal

Actualiza a 0.5.6 o posterior, elige una fuente monoespaciada instalada y vuelve a un zoom cómodo. Este hotfix recupera nombres de fuentes dañados por comillas acumuladas en preferencias antiguas. El margen comparte la fuente del editor.

La búsqueda de actualizaciones no conecta

Comprueba la conexión y pulsa Retry. Abre el enlace de GitHub para consultar las notas de versión. Un fallo de red no significa que se haya instalado una versión nueva.

macOS no puede verificar la aplicación o el paquete

Los paquetes macOS de 0.5.6 no tienen notarización Developer ID. Comprueba el origen y el SHA-256 publicado antes de decidir si abrirlos. Sigue las instrucciones de la versión y los controles de aprobación explícita de macOS; este manual no desactiva las protecciones del sistema.

No se abre una terminal en Linux

Selecciona una terminal instalada en Environment Options o instala una compatible con tu escritorio. Revisa Compile Log por separado para confirmar que la compilación terminó correctamente.

Una biblioteca sigue sin funcionar

Comprueba el sistema operativo de destino, la arquitectura, las dependencias y los argumentos del compilador y del enlazador. El motor completo no proporciona todas las bibliotecas o SDK externos. Aporta un ejemplo mínimo que reproduzca el problema al pedir ayuda.
