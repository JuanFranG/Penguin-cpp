Install the edition you need

macOS 26+ · Apple Silicon

The complete PKG or complete DMG includes the Windows compiler, GNU Make and Wine ARM64/FEX. The small native DMG contains the IDE without that complete Windows environment.

Native macOS programs need Apple’s Command Line Tools. Follow the app’s prompt or use xcode-select --install.

Linux · Ubuntu 24.04 / Mint 22 base

Use the signed APT repository. The IDE package includes LLVM-MinGW/UCRT; APT resolves Make and the private Wine runtime. For a manual download, install both DEB packages together.

Other distributions and architectures need their own validation.

02 / MAKE SOMETHING RUN

Your first C++ program

  1. Create a source file. Choose File → New → Source File, or use New Document on the welcome screen.
  2. Enter this program. It prints a line and exits successfully.
    #include <iostream>

int main() {
    std::cout << "Hello, Penguin!" << std::endl;
    return 0;
}
  3. Save as hello.cpp. Choose a folder you can write to. The .cpp extension tells Penguin to treat the file as C++.
  4. Choose a native compiler configuration. For a first example, select the system compiler’s Release configuration in the toolbar.
  5. Compile and run. Press F11 (fn + F11 on Macs using media keys), or choose Execute → Compile & Run.

A console program opens in a terminal. Its exit summary reports completion and waits for input before closing. You do not need system("pause") just to keep that terminal open.

If compilation fails, inspect the Compiler and Compile Log tabs. Fix the first relevant error and compile again; a failed build does not run an old executable.

Choose a monospaced font in Editor Options → Fonts. On macOS, use ⌘ + mouse wheel or a trackpad pinch to zoom. On Linux, use Ctrl + mouse wheel. The number gutter follows the editor font and adjusts its digit width.

04 / UNDERSTAND THE BUILD

Compile, run, rebuild

ActionKeyResult
CompileF9Builds the current file or project; does not launch it.
RunF10Runs the executable. Rebuild after changing source or build settings.
Compile & RunF11Saves as needed, builds, and launches only after success.
RebuildF12Builds the target again, including sources that need regeneration.

Release, Debug or Profiling?

Release is the usual configuration for running a program. Debug includes information the debugger needs. Profiling instruments native code for the profiler. Changing the configuration is not the same as rebuilding the executable.

Understand an error before changing settings

A syntax error points to source code. A missing header usually means the wrong target or an include path problem. An undefined reference is a link problem: check implementations, libraries and linker arguments. Read the full command in Compile Log when the short error is not enough.

Arguments passed to the running program belong in Parameters. They do not belong in compiler options.

05 / KEEP FILES TOGETHER

Work with a project

  1. Open New Project, choose a suitable template and save the .dev file in a dedicated folder.
  2. Add the source and header files through the Project menu. A header usually provides declarations; its corresponding source must also be compiled when it contains implementations.
  3. Use Project Options for this project’s include folders, libraries, flags and output paths.
  4. Build the project and review the commands in the output panel. Save the project before moving it to another machine.

Keep source files, assets and the project file together. External libraries need the correct platform and architecture; a Windows library cannot simply be linked into a native macOS executable.

Removing a project entry is different from deciding which files to delete from disk. Check the selected entries and keep a backup before using removal or cleanup actions.

A project with a header and several files

This example separates a function declaration, its implementation and the caller. Download the complete project, extract it and open Tutorial.dev with File → Open. Choose your native compiler and press F11. Expected output: Result: 5.

To create it yourself:

  1. Choose File → New → Project, select Console Application and C++, and save Tutorial.dev in a dedicated folder.
  2. Create the three files below in that folder. Use File → New → Source File and save with each complete filename, including the .h extension for the header.
  3. Check that all three appear in the project tree. Add missing files with Project → Add to project. An open editor tab alone does not add a file to a project.
  4. In Project Options → Files, ensure both .cpp files are compiled and linked. The header is included by them, not compiled as a standalone program.
  5. Press F11. Review Compile Log: the build must include both source files, not just the active one.

calculator.h

#ifndef TUTORIAL_CALCULATOR_H
#define TUTORIAL_CALCULATOR_H

int add(int left, int right);

#endif

calculator.cpp

#include "calculator.h"

int add(int left, int right) {
    int total = left + right;
    return total;
}

main.cpp

#include <iostream>
#include "calculator.h"

int main() {
    // TODO: try other values
    int result = add(2, 3);
    std::cout << "Result: " << result << std::endl;
    return 0;
}

What each file does

calculator.h declares add. Its #ifndef / #define / #endif guard prevents repeated inclusion within one translation unit. calculator.cpp defines the function; main.cpp calls it.

Use #include "calculator.h" for this local header. Angle brackets are for system headers or configured library headers. Do not #include "calculator.cpp": add the implementation to the project and compile and link it.

For a missing-header error, check the filename, case and include paths. For an undefined reference or undefined symbol for add, check that calculator.cpp belongs to the project, participates in linking, and matches the header declaration. Rebuild after changing these settings.

Where to set compiler and linker flags

Flags are build-tool arguments. Project-specific options and global compiler configurations have different scopes:

NeedInterface pathUse
Project compiler and structured optionsProject → Project Options → CompilerSelect a configuration and its available options.
Additional arguments for this projectProject → Project Options → ParametersKeep C, C++ and linker arguments in their respective fields.
Header and library foldersProject → Project Options → DirectoriesAdd folders, not each header's filename. Prefer relative paths for a shareable project.
Global structured compiler settingsTools → Compiler Options → SettingsChanges affect the selected configuration, which other projects may also use.
Additional global argumentsTools → Compiler Options → GeneralEnable the corresponding checkbox before entering compiler or linker arguments.
Generated executable and object foldersProject → Project Options → OutputKeep output organised separately from sources.

The example uses -std=c++17 -Wall -Wextra in the C++ field. -std=c++17 selects the language standard; -Wall -Wextra enables warnings. To debug, select Debug and rebuild; -g -O0 supplies symbols and makes unoptimised code easier to follow.

Library arguments such as -L./lib -lname belong in Linker. Execute → Parameters supplies runtime program arguments. An include folder does not replace a library that must be linked. Library binaries must match the target platform and architecture.

After applying changes with OK, rebuild and inspect the actual command in Compile Log to confirm the flags reached the compiler.

06 / SEE WHAT THE PROGRAM DOES

Debug a native program

  1. Select a Debug compiler configuration, then rebuild.
  2. Set a breakpoint on an executable source line with F4 or the breakpoint action in the editor gutter.
  3. Start debugging with F5. Provide keyboard input in the program’s terminal when needed.
  4. When execution stops, inspect watches, the call stack and the paused source line. F7 steps over; F8 steps into a call.
  5. Use F6 to stop the debugging session.

Linux normally uses GDB; macOS uses the available native LLDB tooling. Debug symbols, executable permissions and macOS attachment restrictions still apply. The CPU window needs an active, paused debugger to show live registers or disassembly.

Profile after rebuilding

Use Execute → Profile Analysis. Accept the offered configuration change if appropriate, rebuild and execute the program to produce profiling data. Linux’s gprof view can report timing and a call graph. The macOS LLVM view reports function call counts, not timing. See Profile Analysis for a real example.

Debug this project step by step

  1. Open the example, select a native Debug configuration and rebuild with F12.
  2. Open calculator.cpp from the project tree and set a breakpoint on return total;, line 5, using F4.
  3. Start with F5. The debugger may first pause on entry to main; click Continue in the Debug panel to reach your breakpoint.
  4. Use Add watch for left, right and total. Their values at this line are 2, 3 and 5. Use Evaluate for an expression such as left + right.
  5. Next line steps over calls; Into function enters a call; Continue resumes until another stop; Stop Execution ends the session.

See the actual paused example and its CPU window with registers and call stack. The stack includes add and main. This Mac uses ARM64 registers; names and values vary by architecture and run. Native debugging and running Windows-target programs are separate workflows.

07 / CHOOSE THE RIGHT TARGET

Programs that include Windows headers

windows.h is not a native macOS or Linux API. Penguin’s complete environment can instead compile a Windows executable and run it through its included runtime. Open Tools → Windows compatibility.

ModeWhen to use it
AutomaticThe recommended starting point. Penguin inspects the project’s requirements to select the target.
NativeBuild for the current macOS or Linux system using its native tools.
WindowsExplicitly use the Windows toolchain and runtime when automatic selection is ambiguous.

After the environment reports readiness, F11 performs the build/run flow. Console programs use a terminal; graphical programs use their runtime windows.

Characters, boxes and colours

Use Unicode (UTF-8) for new console text. Try OEM 437 for older DOS-style box characters or ANSI 1252 for code written for that character set. Program-controlled leaves the choice to the program. Recompile after changing the console profile.

This is experimental compatibility, not a guarantee that every Windows project will work unchanged. graphics.h/WinBGIm, Windows-target debugging, third-party SDKs and architecture-specific libraries have additional limits. Standard C/C++ headers such as math.h, stdlib.h and <iostream> are provided by the chosen toolchain; API availability still depends on the target.

10 / RECOVER WITHOUT GUESSING

When something goes wrong

The compiler cannot find windows.h or conio.h

Check the target in Windows compatibility and verify the complete environment. These headers do not become native macOS/Linux APIs. If the program is meant to be portable, replace platform-specific calls with standard C/C++ equivalents.

Characters or box borders look wrong

Check the source encoding and the console profile. Match the profile to the program’s expected code page, then rebuild. A code-page change does not add missing fonts or recreate every historical Windows console behaviour.

No compiler was found

Check Compiler Options → Programs and Directories. Install the platform’s native developer tools when needed. The Windows toolchain in the complete environment is separate from Apple’s native C/C++ tools.

The Windows environment cannot be prepared

Read and copy the error details. Check the compiler/runtime paths and writable private environment folder. Retry after correcting the cause. Keep existing projects and preferences; do not delete them to resolve an unexplained setup error.

The code font or number gutter looks wrong

Update to 0.5.6 or later, choose an installed monospaced font and return to a comfortable zoom. This hotfix recovers font names damaged by accumulated quotation marks in older settings. The gutter shares the editor font.

Check for updates cannot connect

Use Retry after checking the connection. Open the GitHub link to inspect release notes manually. A network failure does not mean a newer version was installed.

macOS cannot verify the downloaded app or package

The 0.5.6 macOS packages do not have Developer ID notarisation. Check the release’s origin and published SHA-256 before deciding whether to open it. Follow the release instructions and macOS’s explicit approval controls; this manual does not disable system security protections.

No terminal opens on Linux

Choose an installed terminal in Environment Options, or install a terminal supported by your desktop. Check the Compile Log separately to confirm that the build itself succeeded.

A library still does not work

Check its target OS, architecture, dependencies, compiler flags and linker flags. The complete runtime cannot supply every external library or SDK. Include a minimal reproducible example when asking for help.

11 / MAKE A USEFUL REPORT

Get help with a reproducible example.

Include the Penguin version, OS and architecture, target mode, selected compiler configuration, steps, expected result and actual result. Add the relevant Compile Log or setup details, a screenshot, and the smallest source file that reproduces the issue. Remove passwords, personal paths and private code before sharing.
